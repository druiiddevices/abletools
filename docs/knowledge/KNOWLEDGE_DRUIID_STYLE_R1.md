# Druiid style system R1

## Status

This is a provisional **musical-behavior profile**, not a claim about a finished Druiid sonic genre. The confirmed identity is deterministic, seed-aware, scale-aware generation with controlled evolution. Do not invent folklore, woodland imagery, “dark organic” clichés, or a fake brand mythology. Sonic specifics should be updated later from the user's own clips, presets, and reference renders.

## Core principles

1. **Seed recallability** — the same seed and settings should produce the same result when the toolchain supports deterministic output.
2. **Scale awareness** — generated pitches remain inside the selected scale unless a deliberate approach, passing, or borrowed tone is declared.
3. **Degree-first harmony** — describe harmonic structure by scale degree before absolute chord names so it transposes cleanly.
4. **Controlled evolution** — variations retain recognizable identity. Change a bounded set of properties rather than replacing everything.
5. **Playable results** — output should drop into an Ableton session and invite performance or further mutation.
6. **Transparent parameters** — important creative controls should map to understandable dimensions such as density, spread, mutation, tension, strum, register, and rhythmic displacement.

## Harmony

- Start from a degree progression or generate one under clear scale constraints.
- `1–6–4–5` is a supported seed archetype, not a mandatory signature.
- Prefer smooth voice-leading and retained common tones.
- Generate inversions and register changes separately from harmonic changes.
- Add color tones only when they remain legible and useful.
- Separate bass movement from upper-voice mutation so either can be locked.
- Useful variation axes: inversion, octave spread, omitted fifth, doubled tone, added 2nd/6th/7th/9th, suspension, rhythmic placement, and chord duration.

## Melody and motifs

- Derive motifs from a small interval or scale-degree cell.
- Repeat with bounded mutation: transpose within scale, rotate, invert selectively, change one interval, displace rhythm, or alter the ending.
- Preserve one or more anchors across variations: contour, downbeat note, rhythm, or cadence target.
- Avoid unrelated random note clouds.

## Bass

- Maintain a clear relationship to the progression while allowing selected anticipations, pedals, fifths, and scalar connectors.
- Favor practical low-register spacing and avoid collisions caused by dense chord voicings.
- Variation should primarily change rhythm, octave, approach notes, or degree emphasis—not all at once.

## Rhythm and groove

- Treat rhythm as a repeatable pattern with named mutation controls.
- Lock the core pulse and vary syncopation, density, rests, accents, microtiming, and probability within limits.
- Humanization must be seeded and bounded.
- Create related A/B/C forms: foundation, restrained mutation, stronger mutation.

## Sound and processing

Until the user provides Druiid sonic references, use neutral, production-ready synthesis and processing. Express the Druiid identity through repeatability, modulation structure, scale awareness, and macro design rather than an invented timbral stereotype.

For presets or chains, useful macro concepts include:

- MUTATE — increases bounded structural or modulation change
- SPREAD — widens voicing, stereo field, or spectral distribution as appropriate
- TENSION — introduces controlled dissonance, filter emphasis, or rhythmic pressure
- MOTION — increases tempo-related modulation depth
- DENSITY — adds events, layers, or partials without uncontrolled gain
- AGE — optional degradation amount; this is a processing dimension, not a required Druiid trait

## Metadata

Every Druiid asset should record:

- seed
- generator/profile version
- scale and root when pitched
- tempo and meter when time-based
- mutation amount or variation relationship
- any non-deterministic stage

Keep observed traits distinct from assumptions. Replace provisional defaults only when multiple examples support the change or the user states it directly.
